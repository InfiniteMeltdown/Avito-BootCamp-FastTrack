# Решение
Сначала пытался задать псевдо-лейблы через SigLIP2 ViT-B/16 и ViT-L/16, но при обычном отсмотре оставалось слишком много ошибок.

Была идея проанализировать эмбеддинги visual backbone'ов, а именно - исходя из предположения о линейности пространства эмбеддингов взять картинку и прогнать через энкодер картинку и ее повернутую версию, вычесть получившиеся эмбеддинги и по направлению результата понять, была ли исхолная картинка флипнутой или нет. 

Более формально, если есть какой-то кодировшик $f$, разница определяется как $$d(x) = f(x) - f(Rx)$$
Где $R$ - поворот картинки на 180 градусов

Таким образом $$d(Rx)=f(Rx) - f(RRx)=f(Rx) - f(x) = -d(x)$$

Значит, направление эмбеддинга разницы строго противоположно повернутой версии картинки. Это можно было бы использовать, если бы был подходящий backbone, но я такого не нашел. ResNet бы слишком сильно пережимал картинку, с нуля обучать не представлялось возможным (нужна сеть с хорошими признаками на разных масштбах восприятия), а уже готовые сети для домена (например PaddleOCR) уже есть в нужной обученной версии. Но потом эта идея пригодилась...

Далее перешел к PaddleOCR, конкретнее к моделям, определяющим положение текста - [PP-LCNet_x0_25_textline_ori](https://huggingface.co/PaddlePaddle/PP-LCNet_x0_25_textline_ori) и [PP-LCNet_x1_0_textline_ori](https://huggingface.co/PaddlePaddle/PP-LCNet_x1_0_textline_ori). Изначальное качество на первой модели было `85.485` и на второй `81.995`. При обычном объединении прогнозов 50/50 качество упало еще сильнее, но при следующем сетапе качество оказалось `94.579`.

Пусть 
- $f_{0.25}$ - вероятность перевернутой картинки `PP-LCNet_x0_25_textline_ori`
- $f_{1.0}$ - вероятность перевернутой картинки `PP-LCNet_x1_0_textline_ori`

Тогда результат модели считается как $$q_{0.25}(x)=\frac{f_{0.25}(x) + 1 - f_{0.25}(Rx)}{2} = 0.5 + \frac{f_{0.25}(x) - f_{0.25}(Rx)}{2}$$

Это нужно, чтобы улучшить качество модели, которая могла обучаться на немного других повернутых данных (усредить качество). Также это отдаленно напоминает мою предыдущую идею про вычитание эмбеддингов моделей.

Аналогично $$q_{1.0}(x) = 0.5 + \frac{f_{1.0}(x) - f_{1.0}(Rx)}{2}$$

Тогда результат ансамбля $$q(x)=\frac{q_{0.25}(x) + q_{1.0}(x)}{2}$$

Затем применяем температурную калибровку $$p_{180} = \frac{q^2}{q^2 + (1 - q)^2}$$

# Выбор решения

Таким образом, есть 2 варианта решения, различающиеся по скорости:
1. `PP-LCNet_x0_25_textline_ori` - одна суперлегкая модель (0.96Mb) со скором 0.87
2. Ансамбль `PP-LCNet_x0_25_textline_ori + PP-LCNet_x1_0_textline_ori` - требует одного прогона через модели 0.96Mb + 6.5Mb, затем аггрегирует результаты.

Соответственно, можно выбрать модель в зависимости от требуемой скорости и качества.
